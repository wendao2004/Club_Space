# 社团空间（Club Space）

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![CI](https://github.com/wendao2004/Club_Space/actions/workflows/ci.yml/badge.svg)](https://github.com/wendao2004/Club_Space/actions/workflows/ci.yml)
[![Node](https://img.shields.io/badge/node-24-339933?logo=node.js&logoColor=white)](.nvmrc)

部署在社团自己的 NAS 上、只对局域网开放的协作平台。桌面式界面，操作习惯贴近 Windows。

> 一个可以**自己部署、数据全在自己手里**的替代品：不用把社团的账目、文件和聊天记录交给任何云服务。
> 单机 Docker 跑得动（8GB 内存的 NAS 实测可用），也适合当作"桌面式 Web 应用"的工程样例来读。

**当前状态：需求里的五项功能全部实现并可运行** —— 工具集（23 个）· 聊天 · 管理员管控 · 记账 · 财物管理 · 娱乐项目（象棋/斗地主/狼人杀），外加桌面外壳与文件系统。

## 它现在能做什么

**桌面外壳**
- 多窗口自由重叠：拖动标题栏移动、拖四边/四角缩放、最小化/最大化/关闭
- 贴边分屏：把窗口拖到屏幕左右边缘自动占半屏
- 任务栏居中排列，显示每个已打开的应用；点图标切换，再点最小化（Windows 的惯例）
- 开始菜单：搜索应用、按分组列出、底部显示当前用户
- 桌面图标：单击选中、双击打开、右键菜单、方向键导航
- 刷新页面后**恢复上次打开的窗口布局**
- 深色/浅色主题；4 套预设壁纸 + **从文件空间选图片当壁纸**（桌面右键「更换壁纸…」）
- **系统音效**：开机、开关窗、最小化/最大化、通知、出错、删除、注销各有不同的合成音（Web Audio 现场合成，零音频文件）；
  任务栏喇叭可调音量（滚轮也行）、一键静音，与「设置 → 声音」同一份状态
- 窄屏自动切换到**独立的移动端界面**（不是把桌面缩小）

**聊天**
- 单聊与群聊，同一套界面
- **实时推送（SSE）**：对方发消息立刻到，不用刷新
- 未读计数与角标（任务栏 + **桌面图标红点**，服务端精确计算）；收到消息时**右下角弹出可点击提示**（点一下直接跳到那个会话）
- 已读回执、正在输入提示、在线状态
- 消息编辑与撤回（**撤回后服务端不再返回正文**）
- 中文全文检索（FTS5 trigram 分词，搜「会议纪要」能找到「我会带上次的会议纪要过去」）
- 文件消息、断线重连后按 seq 增量补拉

**文件**
- 共享空间与个人空间
- 拖拽上传、网格/列表视图、面包屑、筛选
- **大文件分片上传 + 断点续传**（关掉页面再打开，重新选同一个文件会从中断处继续）
- **秒传**（同一空间内 —— 跨空间不生效，否则可用哈希探测他人私人空间）
- 新建文件夹、重命名、移动、删除、下载、右键菜单
- 图片/PDF/文本/音视频预览：**每个预览都是独立窗口**（可拖拽、缩放、最大化、贴边，与其它窗口完全一致；每个文件可各开一个）

**工具集**

| 工具 | 状态 |
|---|---|
| PDF：信息 / 合并 / 提取页码范围 / 旋转 / **删除页面** / **逐页拆分** / **加页码** / **加水印** | ✅ 纯 JS（pdf-lib） |
| **图片转 PDF** | ✅ pdf-lib + sharp |
| 图片：信息 / 格式转换 / 缩放 / 压缩 / **加水印** / **拼接** / **九宫格切图** / **主色调提取** | ✅ sharp（WebP 与 AVIF 能省掉 90%+ 体积） |
| 生成二维码（支持中文） | ✅ 纯 JS |
| **文件哈希 / 校验**（MD5 / SHA-1 / SHA-256） | ✅ 零依赖 |
| **文本工具**：JSON 格式化、Base64、URL 编解码、去重排序、字数统计 | ✅ 零依赖 |
| **随机抽签 / 分组** | ✅ 零依赖（社团点名、抽奖、分组） |
| Word/Excel/PPT → PDF | ⏸ 需按需部署转换服务，见部署指南第 9 节 |
| 视频转码/压缩 | ⏸ 会明确报"还没有可用的服务端实现"，不假装可用 |

> 未启用的工具会**明确显示"未启用"并说明原因**，不会点了没反应。
>
> 有两个能力是**做不到**的，这里说清楚免得反复期待：pdf-lib 不解析 PDF 文本内容，
> 所以"PDF 转文字/Word"做不了；它也不能保存为加密 PDF，所以"PDF 加密"也做不了。
> 另外容器里没装中文字体，PDF 上的文字水印/页码只支持 ASCII（中文请用图片水印）。
>
> 图片工具刻意做成 sharp 的**动态导入**：sharp 是原生模块，某些 NAS 架构可能没有
> 对应的预编译包。动态导入让它在缺失时显示为"未启用"，而不是让整个服务起不来。

**记账（社团报账）**
- 收支流水、分类管理（可归档不可删，历史记录还要引用）
- 报销审批流：草稿 → 待审批 → 已通过/已驳回 → 已支付，**不能跳步**
- **不能审批自己提交的账目**
- 分摊与欠款：谁垫付、谁该给谁多少，可标记结清
- 统计只算**已通过/已支付**的（草稿与待审批不进报表 —— 否则报表会随人随手记草稿而变）
- **金额全程用整数「分」**，连解析字符串都不经过 parseFloat
- 导出 CSV（带 BOM 让 Excel 不乱码，且转义 `=` 开头的单元格防公式注入）

**狼人杀**
- 9 人局：3 狼人 + 预言家 + 女巫 + 猎人 + 3 村民
- **服务端权威的完整状态机**：夜晚（狼刀 → 预言家查验 → 女巫用药）→ 公布结果 → 讨论 → 投票 → 猎人开枪 → 判定胜负
- **按玩家视角裁剪**：别人的身份在你收到的 payload 里**根本不存在**（不是前端藏起来的，控制台也看不到）。
  狼人之间互相可见是规则的一部分；观战者连自己的身份都没有
- 每个角色的可用动作与合法目标都由服务端给出，前端只负责渲染按钮 —— 不重推一遍规则
- 超时兜底：某个人不行动不会把整局卡死（阶段会自动推进）
- 身份分配用 `node:crypto` 的随机数，且**不从任何公开信息可推导**

**财物管理**
- 物品台账：名称/编号/分类/数量/单价/购入日期/存放位置/成色/备注，可导出 CSV
- **借还记录**：谁在什么时候借走了什么、应还日期、逾期多少天、归还时是什么状态
- **可用数量是算出来的**（总数 − 未归还），不存冗余字段 —— 存了就一定会漂移
- 借出在**事务里**校验可用量：两个人同时借最后一件，第二个人会被明确拒绝
- 逾期是派生的，不存字段（它每天都在变）；有东西在外时不能把总数改到比它更少
- **退役而不是删除**：一件东西报废了，它的借还历史仍然留着

**象棋**
- 完整规则引擎自研：蹩马腿、塞象眼、九宫、过河、炮的隔子吃、将帅照面、困毙判负
- 正确性由 **perft 着法计数**保证：初始局面深度 1/2/3/4 = 44 / 1920 / 79666 / **3290240**，与公开已知值精确一致
- 对局房间：创建/加入/观战、实时推送、走子历史、认输与中途退出判负
- **服务端权威**：客户端只提交"我想从哪走到哪"的意图，合法性完全由服务端裁定
- 棋盘用 SVG 绘制：河界「楚河汉界」、九宫斜线、位置标记、选中高亮、合法落点提示、将军脉冲光晕、执黑自动翻转视角
- **人机对战**：三档难度（简单/普通/困难），坐下即开局、不用等人。机器人是**自研的 alpha-beta 搜索**
  （子力 + 位置表评估、静态搜索、杀手着法/历史启发、迭代加深 + 时间预算），
  每步有硬时间上限，不会把 NAS 拖住；简单档会故意走漏着让新手赢得下来。
  另一套为速度重写的走法生成与规则引擎**逐局面差分测试**，不许两份实现分叉
- **绝杀识别**：将死时会报出杀法名 —— 对面笑（白脸将）、卧槽马、钓鱼马、挂角马、双车错、
  立马车、马后炮、重炮、沉底车…… 认不出来就老实说「将死」，不硬凑名字
- **音效**：落子、吃子、将军、绝杀各有不同的合成音（Web Audio 现场合成，不依赖任何音频文件），
  可一键静音并记住

**斗地主**
- 完整牌型引擎：单张/对子/三张/三带一/三带二/顺子/连对/飞机（带单或带对）/四带二（单或对）/炸弹/王炸
- 规则细节都做对了：顺子与连对不能含 2、飞机必须连续、王炸压一切、炸弹只能被更大的炸弹或王炸压
- **三人房间**：叫地主、出牌、要不起、结算
- **手牌按玩家视角裁剪**：服务端在发给你之前就把别人的手牌剥掉了，
  你拿到的是"我的手牌 + 别人的张数"。这不是前端藏起来的 —— 打开浏览器控制台也看不到
- 服务端算好出牌提示（前端不实现牌型判断，避免"前端说合法、服务端说非法"）
- 自动出牌可选
- 反馈效果：我方回合高亮、出牌动画、炸弹/王炸特效、报单报双提示、结算动画

> 关于 **三国杀**（需求里提到但未实现）：它的武将技能本质上是一套复杂的规则引擎
> （触发时机 + 事件总线），工作量大致等于象棋 + 斗地主 + 狼人杀之和，
> 也是最容易做成半成品烂尾的一个。建议放在最后。

**管理与安全**
- 邀请制注册、角色（创建者/管理员/成员）
- **哈希链审计日志** + 数据库触发器禁改，可一键校验整条链
- scrypt 口令哈希、httpOnly cookie 会话、登录失败审计
- **任何格式的文件都能上传**（没有类型白名单）；文件真实类型按文件头（内容）判定、**不采信扩展名**——
  预览只内联位图 / PDF / 文本 / 音视频，SVG 与未知内容一律走下载，防同源 XSS
- **上传没有单文件大小上限**；唯一限制是磁盘余量（写完后至少要剩 2GB，否则拒绝并告诉你还差多少）——那是在保命，不是限额
- **管理员两步验证（TOTP）**：自研实现，通过 RFC 6238 全部 6 条标准测试向量
- **受控运维操作**：白名单式的固定动作（启停指定服务、按模板安装扩展），
  **不提供任意命令终端**；参数只能来自白名单，命令不经过 shell；默认关闭

## 快速开始（本机开发）

本机不需要 Docker：

```bash
pnpm install
pnpm dev          # 后端 :3000 + 前端 :5173
```

打开 `http://127.0.0.1:5173`，首次会显示"创建管理员"。

> `pnpm install` 走的是 `registry.npmmirror.com`（见 `.npmrc`）。如果你的网络能直连 npm 官方源，可以改掉。

跑测试：

```bash
pnpm test                 # 跑全部（约 3-5 分钟，含真实浏览器那一项）
pnpm test:fast            # 跳过需要浏览器的 ui-smoke-test
node scripts/run-all-tests.mjs --only chat-test,games-test
```

单独跑某一项：`node scripts/run-all-tests.mjs --only chat-test`（会自己起服务端、用完清干净）；
直接 `node scripts/xxx-test.mjs` 则需要后端已在 3000 端口跑着。

（它需要一个真实的 Chrome，所以 CI 里跳过，其余 33 个套件都在 CI 里跑。）

`run-all-tests.mjs` 会自动处理：每个端到端测试前重启服务并清空 `data/`。

启用 perft 深度 4（较慢，约 30 秒）：

```bash
XIANGQI_PERFT4=1 node scripts/xiangqi-test.mjs
```

## 部署到 NAS

见 [docs/部署指南.md](docs/部署指南.md)。简要：

```bash
cd deploy
# 1) 生成内网 CA 与证书（含 IP SAN）。
#    ⚠️ 把 IP 换成 NAS 的实际地址，端口与下面 .env 里填的保持一致
cd ca && WL_HOST_IP=192.168.1.100 WL_HTTPS_PORT=9443 WL_ONBOARD_PORT=8080 ./gen-certs.sh && cd ..
# 2) 配置。至少填 WL_SESSION_SECRET，并按第 3 节填好端口与引导页地址
cp .env.example .env && ${EDITOR:-vi} .env
# 3) 数据目录的属主必须对齐容器内的 uid 10001，否则容器能起来但写不进数据
sudo mkdir -p /vol1/docker/wl-club/data && sudo chown -R 10001:10001 /vol1/docker/wl-club/data
# 4) 启动
docker compose up -d --build
```

然后引导成员装根证书，见 [docs/证书分发.md](docs/证书分发.md)。

## 技术栈与关键决策

| 层 | 选型 | 为什么 |
|---|---|---|
| 前端 | Vue 3.5 + TypeScript + Vite + Pinia | 全部 MIT、当前主线版本（已实测核实） |
| 窗口管理 | **自研** | 评测过 winbox（2023 停更）、golden-layout（2022 停更）、OS.js（强锁定），都无法满足"自由重叠窗口 + 任务栏 + 贴边分屏"，皮肤类库（98.css 等）只有外观 |
| 棋盘 | **自研 SVG** | 同上：能画对河界/九宫/位置标记，且完全可控 |
| 象棋规则 | **自研 + perft 验证** | 上游库版本线无法核实（本机拿不到 GitHub/npm 官方源），而规则正确性不能押在无法核实的依赖上 |
| 后端 | Node.js 24（容器与本机，见 `.nvmrc`） + Fastify 5 | 用 Node 原生类型剥离直接跑 `.ts`，无编译步骤 |
| 数据库 | **`node:sqlite`**（内置，WAL） | 省掉一个 250-400MB 的 Postgres 容器；本机无 Docker 也能原生跑 |
| 口令哈希 | `node:crypto` scrypt | 避开 argon2 的原生编译依赖 |
| 会话 | httpOnly cookie + 服务端会话表 | 可即时吊销；localStorage 里的 JWT 做不到 |
| 实时推送 | **SSE 而非 WebSocket** | 零依赖、EventSource 自带断线重连、绕开 WebSocket 的代理 Upgrade 配置坑（详见下文） |
| 中文检索 | SQLite **FTS5 trigram** | unicode61 会把整串中文当成一个词（搜不到），trigram 支持子串匹配，且零额外容器 |
| 金额 | **整数「分」** | 浮点在记账里是灾难：几十笔后余额对不上，用户会认为"软件算错了" |
| PDF | **pdf-lib (MIT)** | 事实核查发现 PyMuPDF 是 AGPL-3.0/商业双授权，闭源分发会触发传染 |
| 时间口令 | **自研 TOTP** | 算法几十行，且 RFC 6238 有公开测试向量可以逐条验证 |
| 存储 | 内容寻址（SHA-256）+ 引用计数 | 自然获得去重与秒传；blob 不可变，备份无撕裂问题 |
| 反向代理 | Caddy 2 | 单二进制、几十 MB 内存、流式转发不缓冲请求体 |

### 几个刻意的"不做"

- **不用 Postgres / Redis / 消息队列**：单进程 + 10-100 人的规模用不上，但会固定吃掉几百 MB —— 而 NAS 留给业务容器的只有 2-4GB。
- **不用子域名**：家用路由器不解析 `*.nas.lan`，子域方案在真实网络里跑不起来。收敛到单一 origin + 路径路由，顺带拿到同源（无 CORS）、单证书、Service Worker 作用域在根。
- **重任务不常驻**：LibreOffice 单实例 1-2GB、ffmpeg 吃满 CPU，常驻必然 OOM 并连带杀掉 NAS 的存储服务。改成按需拉起、用完即停。
- **不提供网页版任意命令终端**：需求原文要"管理员对 Docker 最高权限操控"，但能操作 Docker 就等于能拿到宿主机 root（起一个挂载宿主根目录的 privileged 容器即可）。所以实现的是一组**枚举好的固定操作** + 参数白名单 + TOTP 二次验证。"允许输入命令再拦截危险命令"这种黑名单思路永远能被绕过（`find / -exec sh -c`、`docker run -v /:/host`），只有枚举才是可证明安全的。
- **不做开放注册**：内网平台开放注册等于把入口交给任何一个能连上 WiFi 的人。首次运行自举创建管理员，之后一律持邀请码入场。

## 已知限制（如实列出）

这些都是设计取舍或平台约束，不是待修的 bug：

1. **浏览器无法拦截 Win 键、Alt+Tab** —— 所以"和 Windows 完全一致"在键位层面做不到 100%。平台内快捷键用 `Ctrl+Alt+*`（见"关于本平台"应用）。
2. **无公网 ⇒ 浏览器推送通知（Web Push）不可用** —— 它依赖 FCM/Mozilla 的公网推送端点。通知只在页面打开时显示。关掉标签页就收不到，这个不粉饰。
3. **视频"在线剪辑"是服务端处理**（裁剪、压缩、转封装），不是浏览器里的多轨实时预览 —— NAS 的 CPU 和内存撑不住后者。
4. **格式转换依赖单独部署的转换服务**，默认未启用（内存原因）。
5. **未装根证书的设备功能残缺** —— 见证书指南。
6. **审计是"可检测的不可篡改"，不是"防 root 篡改"** —— 单台 NAS 上任何东西都能被 root 改。能做到的是：哈希链 + 触发器 + 链头外发，事后能查出被改过。
7. **备份的离机副本依赖人工** —— 外接盘需要人换。没有任何自动化能替代"把盘带到另一个地方"这个物理动作。
8. **棋盘类游戏的房间状态用定向推送，不用广播**。象棋的棋盘本身是公开信息，但房间视图里的 `mySide`/`myTurn` 是**因人而异**的 —— 广播一份出去，对手收到的就是落子者的视角（`myTurn` 永远是 false，一步也点不动）。这条踩过，现在所有游戏都走 `pushTo` 按人推；斗地主与狼人杀更是必须如此（隐藏信息）。见 `pushXiangqiRoom` / `pushDoudizhuRoom` / `pushWerewolfRoom`。
9. **娱乐项目还差三国杀**。象棋、斗地主、狼人杀都已完成。三国杀（6-10 周，武将技能本质是复杂规则引擎，最容易烂尾）未做 —— 它的工作量大致等于前三个之和。
10. **管理员管控需要部署时显式启用**（环境变量 + TOTP 秘密），默认关闭。本机没有 Docker，所以**这条路径只有在 NAS 上才能真实验证** —— 我用可注入的执行器覆盖了权限、白名单、命令构造、审计这些安全逻辑，但"docker 命令真的跑通"未经验证。

## 后续可以做的

按"离做完还有多远"排的，不是按有趣程度：

1. **三国杀** —— 需求里提到但没做。武将技能本质是一套复杂规则引擎（触发时机 + 事件总线），
   工作量大致等于象棋 + 斗地主 + 狼人杀之和，也最容易做成半成品。
2. **在线表格** —— 需求里提到"在线编辑表格"，目前没做（CSV 只能预览，不能编辑）。
3. **视频转码/压缩** —— 接口和占位都在，服务端实现没做：会明确报"没有实现"，不假装可用。
   （8GB 内存与"在线剪辑"不可兼得，已确认降级为服务端 ffmpeg 任务。）
4. **Word/Excel/PPT → PDF** —— 代码路径完整，依赖单独部署的 Gotenberg（`deploy/convert/`），
   默认不启（内存原因），需要时 `docker compose -f heavy-tools.compose.yml up -d` 拉起。
5. **音视频通话** —— 需要独立部署 LiveKit 单容器（NAS 上不能常驻），并且必须先把内网 HTTPS 跑通。
6. **更强的棋力** —— 现在的机器人是自研搜索（困难档约深度 5-6，陪社团里的人下够用）。
   想再强一档可以接 Pikafish 的 UCI 子进程（GPL-3.0，内网自用不触发分发义务），
   但那是 1-2GB 内存的常驻重任务，在 8GB 的 NAS 上要按需拉起（见 `heavy-tools.compose.yml` 的思路）。
7. **长将判负** —— 现在只有"同一局面三次判和"。正式的象棋裁判还要区分长将/长捉
   （单方面反复将军要判负），需要逐着判定"是否在将军、是否在捉同一个子"，规则量大，没做。
8. **邮件/短信通知** —— 内网无外网，实际只能做站内通知。

### 关于实时层的选择（记录以免被"优化"掉）

聊天与象棋用的是 **SSE（Server-Sent Events）** 而不是 WebSocket：

- 零依赖，不需要 `@fastify/websocket`，也不用自己实现 WS 的帧解析与 ping/pong
- 通信模式本来就是「客户端发用 POST、服务端推用流」，全双工能力用不上
- `EventSource` 自带断线重连，比手写的重连逻辑可靠
- 绕开了一整类运维坑：WebSocket 需要代理正确转发 `Upgrade` 头，配置漂移的表现是"连不上但没有明显报错"

整个应用只维持**一条** SSE 连接（由 `stores/realtime.ts` 持有），聊天和游戏都通过它订阅事件。
真需要全双工（例如实时协同编辑）时再引入 WebSocket，不必现在预付这个复杂度。
