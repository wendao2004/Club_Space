# 扩展模板目录

这个目录里的每个 `.yml` 都是一个可以在「运维 → 运维操作」里安装的**扩展功能分支**
（对应需求里的"扩展网站的功能分支"）。

## 怎么用

1. 把一个 compose 文件放进这个目录，命名只能用字母、数字、下划线和连字符，
   例如 `jellyfin.yml`
2. 重启 app 容器（或等它下次读取配置）
3. 打开「运维」应用，在「安装扩展」操作里填入模板名（不带 `.yml`）
4. 先执行「拉取扩展镜像」，成功后再执行「安装扩展」

## 为什么模板要由管理员手动放置

平台**不会**从网络下载模板。原因是这个功能本质上是在以宿主机权限启动容器，
如果模板来源可控，它就变成了一个远程代码执行的入口。手工放置意味着：
**能往这个目录写文件的人，本来就已经有 NAS 的访问权限**了，没有扩大信任面。

## 模板里要注意什么

- **不要用 `privileged: true`**
- **不要挂载宿主机的根目录**（`/:/host` 这类）
- **不要挂 `docker.sock`**
- 给每个服务设 `mem_limit` —— NAS 的内存预算很紧，一个没上限的容器会把整机拖死
- 用 `restart: unless-stopped` 而不是 `always`，方便手动停掉
- 端口不要和主栈冲突（Caddy 占了 80/443，app 内部用 3000）

## 卸载

「卸载扩展」执行的是 `docker compose -f <模板> --project-name wl-extension down`。
注意它**不会**删除数据卷 —— 那是有意的：自动删卷很容易在误操作时丢数据。
需要清理时手工删除。
