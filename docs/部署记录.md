## 三、这台机器上做过的系统级改动

一共三处，都可回退：

### 1. `admin` 加入 `docker` 组

```bash
sudo usermod -aG docker admin
```

**为什么必须做**：不加的话 `admin` 连不上 `/var/run/docker.sock`，
部署根本进行不下去。

**代价**：docker 组成员等价于 root（能挂宿主根目录起特权容器）。
fnOS 的 admin 本来就是管理员账号，所以这不算权限扩大，但它确实是永久的。
**要撤销**：`sudo gpasswd -d admin docker`。

### 2. 改了 Docker 的镜像源配置（已备份原文件）

原文件备份在 `/etc/docker/daemon.json.bak-20261017`。

**为什么必须做**：Docker Hub（`registry-1.docker.io`）在这条网络里**不通**，
而飞牛预置的镜像源 `docker.fnnas.com` 实测**是坏的**（返回 HTML 错误页）。
不改的话任何 `docker pull` 都会卡到超时，连 `alpine` 都拉不下来。

新配置里加了四个实测可用的镜像源（daocloud / 1ms.run / dockerproxy / rat.dev）。

**这个改动的副作用**：`live-restore` 是开着的，所以重启 docker 守护进程
**不会**停掉正在运行的容器 —— 实测 `claude-dev-cc-switch` 全程没有被中断。
但重启守护进程这个动作本身仍值得知道。

### 3. 数据目录属主改成 10001

```bash
sudo mkdir -p /vol1/docker/wl-club/data
sudo chown -R 10001:10001 /vol1/docker/wl-club/data
```

**为什么**：容器里的进程以 uid 10001 运行，而这个目录是宿主机绑定挂载 ——
属主不匹配时容器**能正常启动、健康检查也过**，但一建账号、一传文件就报 500。
这个失败模式看起来完全不像权限问题。

## 四、端口为什么是 9443 而不是 443

| 端口 | 谁占着 |
|---|---|
| 80 / 443 / 5666 | 飞牛自己的 nginx（系统 Web 界面，不能停） |
| **8443** | **一个自己跑的 code-server**（本来想用这个，实测被占） |
| 9443 | 平台（最终选择） |

被占的表现是 `wl-caddy` 起不来并报
`failed to bind host port for 0.0.0.0:8443 ... address already in use` ——
那句话不会告诉你"是被别的服务占了"。所以**部署前先 `ss -tln` 看一眼，
不要假设高位端口一定空着**。

## 五、踩到的坑（都已在代码里修掉，这里留个解释）

按撞到的顺序：

1. **引导页端口从没被发布过。** compose 只映射了 443/80，而引导页在容器内的
   8080 上 —— 文档让成员访问的 `:8080/onboard` 根本打不开。
   而它是装证书唯一入口，等于整条进场链路断掉。→ 补上 `8080:8080`。

2. **`:8080/onboard` 路径本来就 404。** Caddy 站点根目录是 `/srv/onboard`，
   请求 `/onboard` 会被解析成 `/srv/onboard/onboard`。→ 加一条 `redir /onboard /`。

3. **引导页把 https 端口写死成 443。** `location.hostname` 会丢掉端口，
   于是探针永远打 443 —— 在 80/443 属于系统界面的机器上，成员装好证书也
   永远看到红灯，装完还被跳到飞牛界面。→ 端口改成由 `gen-certs.sh` 生成配置文件。

4. **引导页用 `crypto.subtle` 算指纹。** 而页面走明文 HTTP，不是安全上下文，
   这个 API 根本不存在 → 指纹永远显示不出来，而那正是页面上唯一防调包的功能。
   → 改成读 `gen-certs.sh` 预先算好的 `ca.sha256`。

5. **iOS 描述文件没有正确的 MIME。** `.mobileconfig` 默认以 XML 发出，
   Safari 只会把 plist 当文本渲染，**不弹安装流程**。→ 加
   `application/x-apple-aspen-config` 响应头。

6. **原设计"执行器自己来取文件、干完回调"是空壳。** 应用往 `/jobs` 发一段
   JSON 带 `callback: /api/internal/jobs/<id>`，而那个路由**在应用里不存在**，
   Gotenberg 也没有 `/jobs` 接口 —— 任何配置下都跑不通，界面上却显示成
   "部署了服务就能用"。→ 改成推送式：直接调 Gotenberg 真实存在的
   `/forms/libreoffice/convert`。

7. **中文文件名会让转换请求直接抛错。** `Gotenberg-Output-Filename` 是 HTTP 头，
   值只能是 Latin-1；Node 的 fetch 遇到中文会抛
   `Cannot convert argument to a ByteString`，而这个错抛在**构造请求**阶段，
   表现为"连不上转换服务"，跟编码毫无关系。→ 头里用 ASCII 化后的名字，
   产物节点名保留中文。

8. **`chown -R app:app /data /app` 会让构建卡死。** 对含有上万个文件的
   `node_modules` 做递归 chown，在 overlay2 + NAS 存储上慢到几分钟不结束，
   进程处于不可中断的 D 状态，从外面看就是"构建卡住了且没有任何输出"。
   → 只 chown `/data`（运行期只往那里写）。

9. **corepack 不认识 `.npmrc` 的 registry。** 它下载 pnpm 时用的是自己的默认源
   `registry.npmjs.org`，在屏蔽了 npm 官源的网络里会卡到超时。
   → 加 `COREPACK_NPM_REGISTRY`。

10. **`.dockerignore` 不存在。** 构建上下文是整个仓库（含 170MB 的
    `node_modules`），而且 `COPY web ./web` 会用 Windows 上装的依赖覆盖容器里
    刚装的 Linux 版 —— `sharp` 是原生模块，跨平台覆盖必然崩。
    → 新建 `.dockerignore`，上下文从 175MB 降到 1.1MB。

11. **`gen-certs.sh` 生成的中文是乱码。** OpenSSL 3.0 默认把 `-subj` 的输入
    当 Latin-1，"社团内网"变成"ç¤¾å›¢å†…ç½‘"，而且**脚本零报错**。
    → 加 `-utf8`。

12. **撒手不管的话，测试会把你的开发数据库删掉。** 测试编排器原本共用 3000 端口
    和 `data/`，跑一次 `pnpm test` 就杀掉你正在用的后端并删库重建。
    → 测试改用独立的 3100 端口和 `.test-data` 目录。

## 六、这台机器上还缺什么

- **`sqlite3` 未安装** —— 备份与恢复演练脚本依赖它，而平台本身不需要它
  （应用用的是 Node 内置的 `node:sqlite`），所以很容易在部署时漏掉。
  启用备份前先 `sudo apt-get install -y sqlite3 rsync`。
- **`restic` 未安装** —— 备份脚本没有实际调用它，不装也行。
- **备份还没配置。** 需要一块**物理上分开**的盘或另一台机器。
  注意 `backup.sh` 会拒绝与数据目录同设备的路径（`/vol1/backup` 这类会被拒），
  这是刻意的：盘坏掉时数据和备份不能一起没。

## 十一、第四轮（象棋棋盘显示）

棋盘的两个显示问题，**两个独立的原因叠在一起**：

1. **裁剪**：viewBox 原点写成 `-PAD`，等于假设"网格从 0 开始"，而网格实际从 0.5 开始。
   可视范围比网格窄 0.38 → 最右一列、最底一行被裁。同时 `PAD=0.12` 比棋子半径 0.44 还小。
   修法：所有坐标从网格边界推导，`PAD` 提到 0.7。
2. **"颜色不对"**：上一轮给 SVG 加了 `width:100%`，`preserveAspectRatio="meet"`
   于是左右各留 84px 透明带，露出窗口底色。修法：SVG 按 `aspect-ratio` 定尺寸，留白消失。

线上已上线，数据未动（用户又新开了棋局，房间数 10 → 11）。

## 十四、第七轮（在线编辑 · 象棋不卡）

**没有迁移**：本地 migration 数量仍是 11，线上 `schema_version` 也是 11，
所以这一轮是纯粹的"换镜像"，数据结构一个字节没动。

内容两块：

1. **Word / Excel 在线编辑**（`SheetEditorApp` / `DocEditorApp` 两个按需加载的 chunk，
   `xlsx` 933KB、`docx` 26KB，都不在首屏包里）。
2. **象棋搜索移出主线程**：`games/bot-runner.ts` + `games/xiangqi-worker.ts`，
   容器里的 Node 24 能直接吃 `.ts`，worker 起得来（见下面的验证）。

**这一轮真正踩到的两个坑，都在"脚本"这一层，不在代码里：**

- **`./upgrade.sh: Permission denied`**。脚本在 git 里是 `100755`，但
  `upload.mjs` 用的 `sftp.fastPut` **只写内容、不改权限位**，落到 NAS 上就是 0644。
  更隐蔽的是：开发机是 Windows/NTFS，Node 的 `statSync` 对任何文件都报 0666
  （没有可执行位的概念），所以"按本地 mode 判断要不要 chmod +x"永远判不出来 ——
  必须查 `git ls-files -s` 里记的 mode。上传脚本已按此修好，`*.sh` 兜底一律 755。
- **`mkdir /home/admin: permission denied`**。`docker build` 起步要建 `~/.docker`，
  而这台机器的 admin 是 uid 1000、`/home/admin` 压根不存在（`/home` 归 root）。
  报错发生在**构建阶段**、且完全不提 docker，像镜像坏了。
  现在 `upgrade.sh` 开头先检查 HOME 可写，不可写就退回到 `deploy/.home`（已进 `.gitignore`）。
  ⚠️ 这个检查必须写成 `${HOME:-}`：脚本开了 `set -u`，而"HOME 没被设"本身就是要处理的形态
  （ssh 非交互执行、cron、systemd 都会这样），写 `$HOME` 会在判断之前就 "unbound variable" 退出。

**升级前后做了什么**：

- 升级前把数据目录打了快照（`VACUUM INTO` 一个一致性副本再连同 blobs 一起 tar，
  8.7MB），留在 NAS 的 `/vol1/docker/wl-snapshots/`，另外拉了**一份到开发机**

## 四十二、第三十五轮（听歌房：同步链路的确定性修复，第 0 步）

**用户反馈**：听歌房仍然"无法保证完整同步"。

**审计**：6 个视角并行审计（时钟 / 切歌时序 / 浏览器生命周期 / 媒体加载 /
输出链路 / 服务端权威性），共 123 条失效模式；3 套方案独立设计 + 6 份对抗
评审 + 综合 + 完备性批评。结论：**不是校正参数不够好，是状态模型和几处
确定性 bug 叠加**。

根因排序：
1. **结构性**：服务端只记"当前进度"，换曲时把 `started_at` 设成服务端
   `now()` —— 而那一刻没有任何一台客户端能出声。每台各自加载、各自 seek，
   切歌瞬间散开 0.1–3.5s；服务端不知道曲目时长，换曲只能靠最先上报
   `ended` 的客户端。
2. **状态会静默死掉**：500ms `setInterval` 被后台节流；SSE 连续 5 次失败
   永久断开不重连；时钟采样失败静默写 0；90 秒 TTL 把后台用户判离开。
3. **确定性 bug**：pause/resume/enqueue/remove 返回房间时漏传 viewerId
   （`inRoom` 恒 false → 本地卸载播放器）；元素被卸载但从不 `pause()`；
   `ended` 用房间当前 token；删文件夹只清根节点。
4. **物理层**：`currentTime` 只是媒体时钟，蓝牙 100–300ms / HDMI 20–150ms
   完全不在模型里。

**顺带纠正**：第三十三轮"11ms"是同机双实例、共享墙钟与声卡的**共模测量**，
测的是控制残差，不能作为跨机同步证据。

**本轮（第 0 步，无数据库迁移）**：
- 服务端：所有变更接口补回 viewerId；心跳返回 `inRoom` 且不 upsert（显式
  离开不复活）；成员 TTL 90→120 秒；`purgeDeletedNode` 递归展开软删子树；
  队列/曲目名过滤 `deleted_at`；刚退场曲目 15 秒取流宽限。
- 客户端：新增 `music-clock.ts`——`performance.now()` 锚定服务端时间，
  采样失败保留旧锚、绝不写 0，未对时不出声并显示"正在对时"，epoch 变化
  与休眠唤醒作废锚点；SSE 永不放弃重连 + 45 秒半开看门狗 + 具名 ping；
  房间 20 秒轮询兜底；load 请求序号防乱序回退；`ended` 绑定元素自己的
  token；换曲/掉出厅显式 `pause` + 清 `src`；进度每 tick 现算（修 computed
  冻结）；听歌房窗口强制单例，恢复布局也去重。

**明确不做（留给下一步）**：未来起播时刻 `startAt`、服务端权威时长与自主
推进、单元素复用 + 预载、输出延迟补偿。这些是精度核心，但会动播放语义，
需要先在两台真机上验证 `play()` 冷启动分布。

**测试**：`music-room-test` 65 → **77**（操作响应 inRoom、心跳语义、删文件夹
不断声）；新增 `music-clock-test` **26 条**（失败保留旧锚 / min-RTT / epoch /
休眠）；全量 **8374 条通过、0 失败**。

**上线**：镜像 `wl-club/app:20261022-174039`（healthy），schema 仍是 v20，
无迁移。升级前数据库快照 `backups/db-20261022-1731/`（停服后 checkpoint 的
单文件一致快照）。旧镜像已留 `prev-20261022-174000` tag。

回滚：
`WL_IMAGE_TAG=prev-20261022-174000 docker compose -f docker-compose.yml up -d app`
（确认后把 `.env` 的 `WL_IMAGE_TAG` 也改回去）

## 四十三、第三十六轮（你画我猜：旁观者画面冻结）

**用户反馈**：你画我猜里旁观者进去只看得到第一帧，之后画面卡住不动。

**根因**：服务端没有"旁观者"这个推送身份。`drawMembers` 只返回
`state.players`，`pushDrawRoom` / `pushDrawStroke` 都只推给他们；而
`onEnterRoom` 在房间已开始时走 `openRoom`（只 GET、不 join）。非成员因此
只拿得到进入时的房间快照与一帧画布，之后收不到任何 `game-draw` /
`draw-stroke` —— 阶段、倒计时、聊天、比分、笔迹全部冻结。

**修复（无数据库迁移）**：
- 服务端新增进程内观看登记：`watchDrawRoom` / `unwatchDrawRoom` /
  `drawRecipients`（players ∪ 未过期 watchers，Set 去重，TTL 90 秒，
  `WL_DRAW_WATCH_TTL_MS` 可覆盖）+ 2 秒 tick 低频清扫；
  `POST /rooms/:id/watch` 返回当前视图供登记后对账，`/unwatch` 幂等。
- `pushDrawRoom` / `pushDrawStroke` 改用 `drawRecipients`；`draw-stroke`
  增加 `roomId`（多画桌不串台）与 `origin`（设备级回声过滤，同账号第二台
  设备也能正确看到笔画/清屏/撤销）。
- 房间解散：leave 前先捕获收件人，只对 404 推 `room:null`；非成员 `leave`
  直接 no-op，不写库、不触发空房解散；非 404 的 DB 错误不再误当解散。
- 泄题修复（审计中发现）：猜对/接近/已猜对者重复发答案，`chat.text` 一律
  置空；drawing 阶段任何归一化后包含答案的发言都不落 chat；大厅列表不再
  返回 `chat`；旁观者只读（`/guess` 403）。
- 客户端：进桌登记 + 20 秒心跳 + 离开注销 + 回前台/SSE 重连强制续期；
  `turnNo` 进入视图（错过一轮 reveal/choosing 时 phase 仍是 drawing，仅靠
  phase 不会清屏）；拉快照加代际 `pullSeq` + 实时笔迹缓冲；画布上下文为空
  时 `drawSegment` 安全返回；`ResizeObserver` 跟随 `canvasBox` 重建；换房
  清空本地笔画簿；刷新按钮同时重拉画布；旁观者隐藏猜词输入；draw 窗口单例。

**测试**：`draw-room-test` 103 → **129**（旁观者 SSE 收画笔/状态、watch
对账、unwatch/重新登记、room:null、非成员 403、已猜对者泄题、
roomId/origin）；`draw-test` 85；`ui-smoke` 392；全量 **8399 条通过、0 失败**。

**上线**：镜像 `wl-club/app:20261022-223419`（healthy），schema 仍是 v20，

## 四十四、第三十七轮（登录时间回填 / 存储页不再跳登录 / 听歌房受全站音量控制）

**用户反馈**：
1. 管理页的用户列表显示"从未登录"；
2. 其他成员点设置里的"存储"会被踢回登录页，刷新后又正常；
3. 任务栏/设置里的声音调节控制不了听歌房的音乐音量。

**根因与修复**：

1. **登录时间**：`last_login_at` 只在口令登录与 TOTP 登录时写；注册也会建
   会话却没有写。会话 30 天有效，用户注册后一直用着会话、不主动登出，
   管理页就永远显示"从未登录"。线上 8 个账号里 6 个是 NULL（注册审计与
   会话记录都在）。
   - `createSession()` 统一写 `last_login_at`（建会话 = 一次登录），以后新增
     任何建会话路径都不会再漏。
   - schema **v21** 数据迁移回填历史：对 NULL 用户优先取审计里的最后
     `login` / `register` / `bootstrap-owner` 时间，其次取现存会话的
     `created_at`；只填 NULL。上线后 8/8 用户都有值，`still null = 0`。

2. **存储页跳登录**：设置里的"存储"调 `/api/admin/overview`，`requireRole`
   抛的是 `AuthError`，全局错误处理把所有 `AuthError` 转成 **401**；前端把
   非 `/api/auth/*` 的 401 当成"会话过期"直接切登录页。刷新后不再自动打开
   该页签，所以"又正常了"。
   - 新增 `ForbiddenError` → **403**：已登录但权限不足不再是"未登录"。
     设置页本来就有"仅管理员可查看"的分支，正好接上。
   - 5 处旧测试断言（记账/财物/2FA/运维）从 401 改为 403。

3. **听歌房音量**：任务栏喇叭与设置里的音量/静音只作用于 WebAudio 音效
   （`sfx` 的 master gain），听歌房的 `<audio>` 没有绑 `volume/muted`，
   永远满音量。
   - 听歌房套用同一份 `soundState.volume`（同一感知曲线 `volumeGain()`）
     与 `soundState.muted`；只改元素音量、不暂停 —— 静音期间时间线照常
     前进，取消静音后位置正确。

**测试**：`db-migrate-test` 14 → **17**（伪装成 v20、塞 NULL 用户 + 注册
审计，重开触发 v21 并断言回填值）；`e2e-test` +1（注册后 overview 的
`last_login_at` 非空）；`user-admin-test` 82 → **83**（普通成员读管理概览
必须 403）；全量 **8404 条通过、0 失败**。

**上线**：镜像 `wl-club/app:20261023-092807`（healthy），schema **v21**
（数据迁移在启动时自动执行）。升级前快照 `backups/db-20261023-0927/`。
旧镜像已留 `prev-20261023-092740` tag。
